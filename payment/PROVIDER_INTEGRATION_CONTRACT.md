# 支付通道适配契约

本文件定义 Westory Visa 内部统一语义。渠道的正式接口字段必须在获批文档到手后映射到这些语义，不能反向修改业务安全边界来迁就不明通道。

## 统一操作

每个真实支付适配器必须提供：

- `create_checkout(order)`：返回渠道订单号、用户可访问的付款 URL/二维码内容和过期时间。
- `query_order(provider_order_id)`：返回统一支付状态、渠道交易号、金额、币种和完成时间。
- `verify_and_parse_notification(raw_body, headers)`：先验签和校验时效，再返回统一事件。
- `create_refund(payment_id, amount, reason)`：使用本地退款 ID 作为幂等键。
- `query_refund(provider_refund_id)`：返回统一退款状态和完成时间。
- `download_reconciliation(date)`：提供可审计的日对账数据或明确的替代接口。

## 统一状态

支付：

- `creating`
- `pending`
- `paid`
- `failed`
- `expired`
- `partially_refunded`
- `refunded`

退款：

- `creating`
- `pending`
- `succeeded`
- `failed`

渠道出现未知状态时必须保留为待核查并告警，不能默认成功。

## 下单安全要求

- 商品、金额、币种和有效期只从服务端数据库读取，不接受浏览器传入价格。
- 渠道商户单号使用本地订单 ID，或保存可唯一反查的映射。
- 必须设置确定的异步通知 URL；前端 `return_url` 只用于展示结果。
- 支持渠道幂等键时必须使用本地订单 ID；不支持时由数据库唯一约束防重。
- 记录条款版本和服务器接受时间后才能创建渠道交易。

## 通知安全要求

- 在解析业务数据前完成渠道规定的签名/证书验证。
- 校验时间戳或 nonce，并执行渠道要求的重放保护。
- 校验本地订单存在、机构一致、金额完全相等、币种完全相等。
- 只接受合同和文档列出的终态；浏览器跳转、截图或客户端字段不能标记成功。
- 按渠道事件 ID 建唯一记录；渠道无事件 ID 时使用经审查的稳定字段构造去重键。
- 通知响应严格遵循渠道文档，避免无限重试。

## 退款与会员要求

- 可退款额由本地已成功/处理中退款总额锁定，防止并发超额退款。
- 渠道返回处理中时不得提前视为成功。
- 退款成功后重新按全部有效付款和退款计算会员期限，不直接减固定天数。
- 原路退款失败必须进入人工处理，不得静默关闭记录。

## 日志与敏感数据

- 可记录渠道请求 ID、订单号、状态码和脱敏错误。
- 不记录私钥、API 密钥、证书口令、完整身份证件、银行卡号、钱包凭证或原始敏感回调字段。
- 原始回调如为审计所需，应加密、限制访问并设置保留期限；默认只保存哈希和必要的规范化字段。

## 上线门槛

适配器只有在自动测试覆盖成功、失败、伪造签名、错金额、错币种、重复通知、乱序通知、查单、退款和并发退款后，才能允许 `configured=true`。
